How Chrome Remote Desktop does it on a phoneFrom Google's help and the open client code in Chromium (remoting/client/ui: DesktopViewport, GestureInterpreter, TrackpadInputStrategy, TouchInputStrategy)

Two modes

  • Trackpad (phone default): the screen is a laptop trackpad. The finger moves the cursor relatively, from anywhere; it never covers the target.
  • Touch (tablet default): the cursor jumps to the finger. Fast, but the finger hides small targets.
  • A toolbar (hamburger / three-finger swipe) holds the keyboard, mode switch, Ctrl-Alt-Del, disconnect.
  • The cursor shape comes from the host as its own message and is drawn by the phone, so it moves with no lag even when video lags.

Why the zoom "follows the mouse"

  • The viewport is centered on the cursor after every move: viewport.center = cursor.
  • It is then clamped to the desktop, so at an edge the view stops and the cursor walks to the edge of the phone instead.
  • Zoom is clamped between "whole desktop fits" and about 1:1 device pixels and above.
  • When the keyboard opens the viewport's safe area shrinks and the view re-centers, so the cursor sits above the keys.
